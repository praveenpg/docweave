Observation (CompareUpstreamPageOrder, page 1, development originals recent/next/elife):
  In every native profile, the upstream element holding author names with affiliation markers is
  unlocated in DocWeave text. The private first-divergence probe shows DocWeave emits the raised
  affiliation markers of that author line as a separate physical line placed before the names;
  upstream keeps each marker inline after its name. Affiliation lists show the same class.

Root-cause hypothesis:
  Native upright line grouping (PdfGlyphLines) starts a new row whenever a glyph baseline differs by
  more than 2 units. Short raised/lowered small-glyph runs therefore become standalone rows.

Single candidate (one explicit, opt-in native policy; defaults unchanged):
  Before native upright line grouping of ordinary (non-table) text, reuse the existing bounded
  small-glyph run rule already used for cells and tagged paragraphs: runs of at most 8 nonblank
  upright glyphs at most 0.75 x page median height, connected by small advances; assigned only when
  exactly one nearby body baseline (median-height glyphs, horizontal gap at most max(2, 1.5 spaces),
  vertical shift > 2 and <= 0.8 body height) supports the complete run; competing baselines,
  overlaps or longer runs keep original grouping. Only the grouping baseline changes; every source
  character, glyph bound and element coordinate is retained. Body lookup must be bounded by a
  baseline-band index so work stays linear in glyphs, with the existing page work/cancellation.
