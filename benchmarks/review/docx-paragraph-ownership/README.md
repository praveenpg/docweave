# Owned DOCX paragraph ownership evidence

These are project-owned fixtures and stored-XML diagnostics, not independent Word
rendering expectations. The manifest pins input bytes and generator provenance.
`content-ownership.docx` is generated by CreateDocxContentFixture.java; `nested.docx`
is an exact copy of the existing nested-table baseline, not a new independent input.

Both default and stored-header/footer extractions pass ownership-v1:

| Fixture | Owners | Nonblank paragraphs | Unmatched | Unexpected body/text-box elements |
| --- | ---: | ---: | ---: | ---: |
| Content | 9 | 13 | 0 | 0 |
| Nested tables | 1 | 9 | 0 | 0 |

The content fixture exercises a separate anchored text-box paragraph, accepted
revision text, content controls, cached fields and merged table content. Notes,
comments and image elements are deliberately outside the ownership oracle's body
scope. Text boxes rooted in those other parts are excluded transitively; unknown
parents and cycles remain failures. The nested-table fixture requires two separate occurrences of a repeated
paragraph in one flattened table. Its three NESTED_TABLE_FLATTENED warnings are
explicitly expected; unexpected or missing warning codes still fail the contract.

## Ownership-v1 scope

Ownership-v1 now lives in the Java/JUnit [validation module](../../../docweave-validation/README.md).
The Python ownership implementation and CLI mode have been removed. Saved reports
here retain their historical Python source hashes; the default legacy substring
checker is unchanged. Ownership remains candidate-only because upstream mappings
are not defined.

The XML oracle gives each nonblank body paragraph and root table an owner keyed by
structural XML path. Text-box paragraphs/tables have separate owners anchored to
the containing paragraph or flattened root table; nested boxes anchor to their
own containing emitted element. Text never leaks from a box into its host's
paragraph expectation. Deleted/move-from ancestors and deleted table rows are
excluded under the default ACCEPTED policy; properties are excluded and cached
field results are read without evaluating instructions.

Output owners are mapped in order within the body and each text-box parent-ID
queue. Paragraph owners require NarrativeText/Title/ListItem, table owners require
Table. Within each owner, normalized paragraph strings need nonoverlapping output
intervals. One occurrence cannot satisfy duplicate paragraphs. Longest-first greedy
allocation can fail on ambiguous overlapping substrings; failures are diagnostics,
not automatic proof of a production extraction defect. Extra body/text-box elements
fail. Headers, footers, notes, comments and images remain outside this oracle.

The check does not establish exact text equality, table cell ownership or reading
order, symbol-font glyph accuracy, interactive controls, layout or rendering. Table
paragraph order is deliberately not enforced because merge content can move. An
element's owner identity is inferred from order/type/parent metadata, not a source
position exported by the Java parser. Unsupported block wrappers, AlternateContent
story selection, nested paragraphs outside text boxes, and boxes in blank host
paragraphs fail closed. Those require a future baseline version rather than a guess.

## Reproduce

From repository root, without Python or a launcher classpath:

```sh
mvn -pl docweave-validation -am test
```

New generator runs can change DOCX ZIP bytes; do not replace pinned input hashes or
historical reports implicitly. Independent adversarial JUnit tests remove duplicate
text, alter body order/type, relocate box text/parents, add unexpected elements and
exercise nested/sibling box ownership. They use owned XML and fake outputs without
network or Python. The Maven suite also runs the real Java extractor on the pinned
inputs. No Windows VM is required.

The separate review-body-scope.json repeats the real-extractor checks after adding
transitive other-part text-box exclusion. Counts remain unchanged; the initial
review.json retains its original implementation hash. The other-part, orphan and
cycle scope cases are tested with deliberately constructed element metadata.
