# Attribution of the multi-page model-layout failures

This is a numeric stage audit, not a new extraction policy or another quality score. The
manifest freezes the original source/model identities, prior model experiment, prior parent
geometry report and finalized JVM audit-tool hash before first execution. Reference labels,
statement ROIs and publisher text never enter the audit tool. It renders and infers every
original page at150DPI with the same pinned graphs, four CPU threads, threshold0.5,
30-second shared page deadlines, higher-score structure conflicts and existing crop planner.

`CaptureNativeDetectorStages.java` records thresholded detector objects before crop planning,
actual bounded integer crops, crop-relative structure objects and pre-final-rejection table
topology. It does not change production code or expose a new library API. Output contains
numeric predictions only; no PDF, raster, model weight or publisher text is redistributed.
This stage diagnostic is separate from the production transaction and its final ownership,
combined native/model budgets and cross-candidate rejection.

Actual Java21/25 stage reports agree on all11 original pages after removing only runtime.
The four selected parent layouts reproduce the previous production capture's dimensions
and displayed bounds within0.001point. Frozen audit/tool/source pins are verified.

Each of these pages has exactly one thresholded ordinary-table proposal and one planned crop.
Duplicate suppression cannot explain these particular losses: the merged/narrow regions
already exist in the detector output. Fixed10pixel crop context cannot restore the much wider
missing label column or split the merged pair. Structure inference cannot recover pixels
outside its input crop. Page5 also has34 thresholded row objects versus32 final logical rows,
which is a separate possible structure-quality issue; it does not explain the initial merge.

The previous strict statement scores remain0/110; the earlier3/6 geometry associations are
not promoted to semantic recovery. This is no accuracy gain, no reason to change defaults
and no evidence of a coordinate-translation bug on these four outputs. Next work should
evaluate a source-independent detector improvement or alternative provider, retaining the
fixed failures and earlier regression populations. A reference-guided crop or source-specific
boundary patch would not validate that improvement.

The standalone tool requires explicit PDF/hash, detector/hash, structure/hash and a fresh
report path, in that order. Use `-Djava.awt.headless=true --enable-native-access=ALL-UNNAMED`
and the project's runtime classpath. No download or model discovery occurs. It requires a
10MiB-or-smaller original, at most1000pages and16M render pixels per page. Strict private
Javadocs, compilation and the pinned formatter pass. The prior full product verification
remains1,109 tests on both actual JDKs; no production source changed in this audit.
