# DocWeave 0.1.0-beta.8

Status: verified and installed locally; not signed, tagged, published to GitHub or uploaded to Central.

## Changes and upgrade impact

All library Java packages move from `dev.docweave` to `io.docweave`. Maven coordinates retain the
`io.docweave` groupId and existing artifactIds. All dependencies use version `0.1.0-beta.8`.
Update imports, custom SPI implementations/descriptors and reflection names, then rebuild all
consumers. This is a source/binary breaking change; there are no old-package aliases.
See [migration guidance](../package-migration.md).

The candidate includes the previously unpublished beta.7 changes; see [beta.7 notes](0.1.0-beta.7.md)
and the Unreleased changelog for cumulative functionality and limitations. Namespace migration is
not a new extraction-quality improvement. Java 21 remains the minimum, without preview APIs.

## Local usage and verification

Run `mvn clean install` with Java 21 to verify and install the candidate into the local Maven
repository. Source/Javadoc attachments are prepared with the `release-artifacts` profile; that
profile does not sign or upload artifacts. Java 21 full reactor verification passed 1,461 tests with zero failures/errors/skips and strict
Javadocs. A standalone Maven consumer passed all native format discovery/extraction, HTML SPI,
PDF, chunking/JSON and optional adapter API linkage checks using only installed JARs. Runtime
JARs contain no old `dev/docweave` class paths or old SPI descriptors. No OCR engine, ONNX model
or live provider was executed. Source and Javadoc JARs are installed alongside runtime artifacts.

Published beta.6 artifacts remain unchanged. This candidate is not on Maven Central. Public source
synchronization, signing, tags, GitHub release notes and publication require a separate release step.
