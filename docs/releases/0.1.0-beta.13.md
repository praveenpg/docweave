# DocWeave 0.1.0-beta.13

## Release status

State: **proposed; not yet published**. Full-library scope includes the parent and every deployable library module.
Integration and validation harnesses and the separate Studio SDK are excluded. Jenkins will verify the exact public
source, create an annotated `v0.1.0-beta.13` tag and GitHub prerelease, sign the captured artifacts, then validate and
publish them to Maven Central. The previous Central release is 0.1.0-beta.12; its coordinates remain unchanged.

An internal beta.13 build already exists. The Central release is independently built and verified from the public
source. Builds are not byte-for-byte reproducible; internal artifacts must not be substituted for Central artifacts.
This release does not change Studio's internal library pins or deploy Studio.

## Changes

PDF pages are processed concurrently using `parallelStream()` on the common fork/join pool. Batches contain at most
pool parallelism plus one pages, and completed pages are emitted in input order. Element order and IDs, warning order,
reading-order metadata, metadata key order and cross-page table continuation are preserved. Other formats are unchanged.
See the [complete changelog](../../CHANGELOG.md#010-beta13) and [parallel PDF contract](../pdf-page-parallelism.md).

Each worker opens its own PDFBox reader over the same read-only input. The image-byte budget remains shared; per-page
operator, graphics-state, image-occurrence and geometry safeguards remain in force. Progress advances after ordered
emission; a failed batch reports no progress for its buffered pages. Cancellation interrupts this call's page callbacks,
stops siblings after the first failure and waits for every page task before returning, provided providers honor their
existing interruption contracts. No interrupt is left on a pool worker.

## Usage and upgrade

```xml
<dependency>
    <groupId>io.docweave</groupId>
    <artifactId>docweave-pdf</artifactId>
    <version>0.1.0-beta.13</version>
</dependency>
```

- Java 21 or later, without preview APIs. Align all DocWeave modules to beta.13.
- No public API, option, default or dependency changes since beta.12; no data migration is required.
- Parallel PDF processing has no new setting or sequential fallback. The common pool is shared with other callers.
- Worker-local readers increase peak memory with pool size. Size deployments using representative native, OCR and
  HI_RES documents; this release does not promise a universal speedup or a fixed memory budget.
- OCR and table-layout providers may receive concurrent, out-of-page-order callbacks under their existing thread-safety
  contracts. Their process/inference limits still apply. A caller running in the common pool waits using a managed
  blocker and does not run page callbacks inline.
- When upgrading from older versions, the [beta.12 breaking changes and bounds](0.1.0-beta.12.md) also apply.

## Verification

Publication is conditional on full Java 21 reactor tests, strict Javadoc, required S3-compatible tests, archive/license/
bytecode checks, independent OCR/layout adapter consumers against the exact captured artifacts, signing, durable
candidate storage, Central validation and public-checksum verification. The S3Mock helper uses Java 25; library
compilation and tests remain Java 21. Internal build results do not establish that this Central candidate has passed.
Final candidate, build, test and publication evidence will be recorded after completion.

## Known limitations

The [beta.12 limitations](0.1.0-beta.12.md#known-limitations) remain. Optional engines/models need explicit configuration;
PDF/OCR quality retains its documented boundaries; compatible S3 testing is not AWS qualification, and Native Image is
not qualified. Parallelism adds reader memory overhead and shares the common pool with unrelated work. Provider
callbacks must honor cancellation before the synchronous call can finish stopping its tasks.
