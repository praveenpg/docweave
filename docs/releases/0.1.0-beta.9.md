# DocWeave 0.1.0-beta.9

## Release status

State: **prepared full-library candidate; publication pending**. All reactor modules use `0.1.0-beta.9`.
The release selects every deployable library module; integration/validation harnesses are not published.
Jenkins will record the exact public source revision, immutable signed candidate and Central deployment receipt.
The annotated tag is `v0.1.0-beta.9`; no existing artifact or version is replaced.

## Changes

- Remote inputs: `DocumentSource.remote(location)` passes an opaque string to an explicitly configured
  `RemoteSourceResolver`. Core remains JDK-only. Acquisition enforces byte limits, a finite timeout and
  interruption, with owned-resource cleanup and source provenance. See the [tutorial](../remote-sources-tutorial.md).
- New optional `io.docweave:docweave-source-s3` module supports explicit AWS SDK v2 client/credentials configuration,
  S3-compatible endpoints, object versions, bounded downloads and generation-pinned retries. It is not included
  in the all-formats artifact and does not execute network requests merely because its JAR is installed.
- Independent abort callbacks cannot block other resolutions' stop handling. A response-release failure closes
  already-acquired content instead of leaking its spool file.
- Includes the cumulative format, OCR/layout, chunking, JSON and PDF work since the last full publication.
  Beta.7 was unpublished and beta.8 published parent/core only. See [beta.7 notes](0.1.0-beta.7.md),
  [beta.8 notes](0.1.0-beta.8.md), the [changelog](../../CHANGELOG.md) and [PDF support](../pdf-support.md).
- The frozen PDF crop-image contract compares decoded pixels rather than environment-dependent PNG encoding.
  Independent Tesseract/ONNX consumers resolve the exact selected version and captured artifact hashes.

```xml
<dependency>
    <groupId>io.docweave</groupId>
    <artifactId>docweave-pdf</artifactId>
    <version>0.1.0-beta.9</version>
</dependency>
```

For remote S3 inputs, add `docweave-source-s3` at the same version alongside the desired format module and configure
its resolver explicitly. Follow the tutorial for credentials, endpoint configuration and resource ownership.

## Upgrade and compatibility

- Java 21 minimum; no preview features. Java 25 is used only for the S3Mock test helper, not library bytecode.
- Packages use `io.docweave`. Users upgrading from published full beta.6 must migrate `dev.docweave` imports,
  SPI descriptors and reflection names; see [package migration](../package-migration.md).
- All DocWeave module versions must align. Parent artifact is `docweave-parent`; the all-formats artifact is
  `docweave` and keeps external OCR/layout and remote-provider integrations optional.
- `DocumentSource` gains a sealed `Remote` subtype: consumers with exhaustive switches must add a case.
- `PartitionResult` gains `sourceProvenance`; the previous six-argument constructor is retained. Record equality,
  reflection and record-component consumers must account for the additional component.
- Existing File, Bytes and Text inputs retain their behavior. Remote acquisition is opt-in; parsers still operate
  on acquired local content, and temporary-file spooling does not make parsing streaming.
- OCR needs an explicitly configured Tesseract executable/language data; ONNX layout needs explicitly supplied
  models and platform-native support. No automatic executable or model downloads occur at runtime.

## Verification

Development source passed Jenkins Java 21 full-reactor verification: **1,512 tests, zero failures, one expected
skip**. The skipped denial scenario is not enforced by S3Mock; SeaweedFS qualification covers denial separately.
The five other S3Mock scenarios passed. The S3 fault tests passed 12/12 and location tests 3/3.
Both independent remote-source review probes pass on the corrected source.

Before publication, the release pipeline must repeat verification with the release version and source/Javadoc
attachments, strict Javadocs, archive/license/Java-21-bytecode checks and independent adapter consumers against the
captured candidate. Signing, validation and public checksums are separate recorded release gates. Development
results above do not claim those publication gates have already completed.

## Known limitations

- Remote S3 acquisition is qualified against S3Mock and SeaweedFS, **not real AWS S3**. No AWS support claim beyond
  the documented API and compatible-service evidence is made.
- An abort action that itself blocks can still delay its own resolution; it no longer blocks other contexts.
- HTTP, Azure Blob and GCS resolvers are not included; applications may implement the open resolver contract.
- PDF/OCR/table-layout quality retains the documented format/provider limitations. Development fixture results
  are not a general extraction-accuracy guarantee; see [compatibility](../compatibility.md).
- Native Image compatibility is not qualified. Optional native integrations remain platform-dependent.
