# DocWeave 0.1.0-beta.10

## Release status

State: **published to Maven Central on 1 November 2026**. Full-library scope: 18 deployable artifacts
(parent plus 17 library artifacts), with 69 canonical POM/JAR/source/Javadoc files, all using `0.1.0-beta.10`.
Integration and validation harnesses and the separate Studio SDK are not published.

Jenkins Central release #82 verified and signed public source `282260c7740b1c62a6fa08ab9ebd66292e598c3c`.
Central deployment: `d51fcacc-ca13-4890-8949-19d7ba43d12d` (`PUBLISHED`). Annotated immutable tag and GitHub prerelease:
[v0.1.0-beta.10](https://github.com/praveenpg/docweave/releases/tag/v0.1.0-beta.10).
All public artifact hashes match the signed candidate. Existing beta.9 artifacts and tags are unchanged.

## Changes

This is an explicitly requested maintenance release with **no runtime, public API, dependency or default changes
since beta.9**. It advances the coordinated artifact version and release documentation; it does not claim new
parsing functionality or fixes. See the [beta.9 notes](0.1.0-beta.9.md) for the unchanged functionality.

```xml
<dependency>
    <groupId>io.docweave</groupId>
    <artifactId>docweave-pdf</artifactId>
    <version>0.1.0-beta.10</version>
</dependency>
```

## Upgrade and compatibility

- Java 21 minimum, without preview features; library bytecode remains Java 21. The S3Mock test helper uses Java 25.
- All DocWeave module versions must align. The parent remains `io.docweave:docweave-parent`, and the all-formats
  artifact remains `io.docweave:docweave`. Optional remote S3, OCR and layout integrations remain opt-in.
- Moving from beta.9 requires only the dependency-version change; it introduces no source or data migration.
  Earlier-release migrations described in the beta.9 notes still apply when skipping beta.9.
- Published beta.9 coordinates and bytes are not replaced. This release does not upgrade or deploy Studio.

## Verification

Jenkins library CI #26 and Central release #82 each passed full Java 21 verification: **1,512 tests, zero failures,
one expected skip** (S3Mock does not enforce access denial; separate compatible-service qualification covers it).
Strict Javadocs, required S3Mock scenarios, archive/license/Java-21-bytecode checks and standalone optional-adapter
consumers passed. The release signed and stored the canonical candidate, created the annotated tag/prerelease,
validated and published to Central, then matched all 69 public artifact hashes to the signed bytes.

A clean Java 21 consumer using core and TXT jars downloaded directly from Central passed parser discovery,
explicit remote resolution, source provenance and local/remote element parity; both jars matched the canonical
hashes. No Java source file differs from beta.9. No paid model call or Studio deployment was involved.

The next runtime-development version is `0.1.0-beta.11-SNAPSHOT`, to be selected on dev before any runtime change.
This documentation-only completion leaves the release source version at beta.10; it does not publish a snapshot.

## Known limitations

The [beta.9 limitations](0.1.0-beta.9.md#known-limitations) remain unchanged: compatible-service S3 qualification is
not real AWS S3 qualification; HTTP/Azure/GCS remote resolvers are not included; optional OCR/layout engines and
models require explicit configuration; PDF/OCR quality retains its documented boundaries; Native Image is not
qualified. No additional compatibility or extraction-quality claim is made by changing the version.
