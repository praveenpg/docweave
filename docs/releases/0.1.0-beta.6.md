## Added and usage

Explicit native PDF text with provider table layout:
`PdfPartitioner.createWithNativeLayout(PdfOptions, PdfNativeLayoutOptions, PdfTableLayoutProvider)`.
Caller-owned geometry supplies complete rows/cells/spans; original native glyphs provide text,
with single ownership, retained unclaimed text/images and complete bounded topology validation.
Use an existing explicitly configured ONNX layout provider without requiring an OCR engine.

```java
// layout: caller-owned, thread-safe PdfTableLayoutProvider, such as OnnxTableLayout.create(...).
var pdf = dev.docweave.partition.PdfPartitioner.createWithNativeLayout(
        dev.docweave.partition.PdfOptions.defaults().withTableCellCoordinates(true),
        new dev.docweave.partition.PdfNativeLayoutOptions(150, 16_000_000, 1024), layout);
var registry = dev.docweave.partition.PartitionerRegistry.of(java.util.List.of(pdf));
var result = dev.docweave.DocWeave.create(registry).partition(java.nio.file.Path.of("report.pdf"));
```

The application owns managed model lifetime; close it after all extraction calls finish.
No automatic model downloads, provider execution at construction, OCR or extra executor.

Provider tables can now carry a declared top header-row prefix. Native provider layout, word OCR
and cell OCR expose positive declarations as `pdf_table_header_rows` plus
`pdf_table_header_policy=provider_declared_prefix_v1`. ONNX uses class3 geometry and a strict
contiguous prefix from row0. Header levels, cell spans, `<td>` markup and text remain unchanged.
Zero/absent means unknown or no declaration. This supplies context for later refinement; it does
not repair the2/214 education result or certify semantic headers.

Explicit source-tagged tables are available through `PdfPartitioner.createWithTaggedTables`
and `createWithTaggedTablesFirst`. See [scope and fallback rules](../pdf-support.md#explicit-source-tagged-tables).
This adds interface factories without changing existing factory behavior or record shapes.
Tagged ownership also validates known PDFBox content-stream ActualText substitutions while
retaining rejection of ambiguous later mutations. The fixed publisher development table
improves131/136 to135/136 exact span/text anchors, with136/136 logical span keys and9/9
headers; one word-wrap mismatch remains. This is one development case, not general accuracy.

Explicit `RULED_AND_SEGMENTED_ROWS` retains closed/partial detection and adds bounded source-rule
body row-span inference. It needs matching segmented outer rules, first-column separators and
contained nonblank text. Geometry and spans remain inferred; no semantic headers are declared.
One eLife table improves12/20 to20/20 exact logical span/text anchors, with all22other selected
regions unchanged. Existing modes/defaults stay unchanged; no public record shape changes.

## Upgrade and runtime

Existing factories and native table strategies remain available. `PdfTableLayoutProvider.Table`
adds a sixth record component, `headerRows`. The original five-argument constructor and accessors
remain available, with a zero default; a consumer compiled against the former constructor runs on
both verified JDKs. Source record patterns must add the component; reflection/record serialization,
equality, hash and string consumers must account for the extended record shape. Existing explicitly
configured ONNX providers can now emit additional header metadata. No row merging is enabled.
Java21 or later is required; Java21/25 are verified, with no preview APIs. Maven groupId
remains `io.docweave` and Java packages remain `dev.docweave`. The PDF module adds no dependency;
optional ONNX remains separate. Align explicitly selected module versions when a release exists.

The new factory replaces native table heuristics on native-text pages. Empty provider output
retains ordinary text rather than falling back to another table strategy. Textless pages keep
images/warnings without OCR/provider invocation. Declared page/native-baseline quarter turns are supported in the displayed frame; arbitrary
native angles still fail explicitly. Crop/UserUnit and source image placements remain supported.

## Known limitations

One issuer/two development tables are not held-out accuracy or independent physical-cell/span
labels. Model accuracy, native font/Unicode quality, semantic reading order, native/OCR
arbitration and broad scan quality remain separate. Provider tables do not generate native
ruled-table continuation signatures. Shared topology validation uses `OCR_FAILURE` for invalid
provider output even though no OCR runs. Rendering uses pixel ceilings, not a peak-memory or
total-document deadline guarantee; provider deadlines remain caller/provider responsibilities.

See the [contract](../pdf-support.md#explicit-provider-geometry-with-native-text),
[evidence](../../benchmarks/review/pdf-native-provider-layout/README.md) and
[completion gates](../pdf-completion-plan.md). The planned DocWeave/Unstructured comparison
matrix is a completion deliverable, not a claim of current parity.

## Explicit native-first composition

`PdfPartitioner.createWithNativeTablesFirst` retains accepted native topology and assigns only
exactly unclaimed glyphs to disjoint provider tables. Every raw provider output is validated;
partial interior overlap rejects the whole provider candidate. Errors are not hidden by native
success, and accepted native anchors plus all raw provider anchors share the page ceiling.

```java
var nativeOptions = dev.docweave.partition.PdfOptions.defaults()
        .withTableDetection(dev.docweave.partition.PdfOptions.TableDetection.RULED_AND_PARTIAL_TEXT)
        .withTableCellCoordinates(true);
var pdf = dev.docweave.partition.PdfPartitioner.createWithNativeTablesFirst(
        nativeOptions, new dev.docweave.partition.PdfNativeLayoutOptions(150, 16_000_000, 1024), layout);
```

Closed, partial, horizontal and double-rule policies support exact glyph staging. The two
run-based aligned policies are rejected by this factory; their existing factories remain available.
This explicit precedence policy is not calibrated confidence or an automatic default change.
With one uniform policy on the existing development set, financial improves102/440 to440/440
CSV positions and statistics72/350 to339/350 versus provider-only; procurement152/154,
recent59/59 issuer rows and scientific43/43 span/text anchors remain. Nine new owned controls
cover disjoint/overlapping tables, exact retained glyphs, invalid provider/failure causes,
combined anchors/shared work, transformed frames and model-only/textless pages.
See [the contract](../pdf-support.md#explicit-native-first-table-composition) and
[paired evidence](../../benchmarks/review/pdf-native-first/README.md). This milestone is
included in the cumulative beta.6 release; current publication status is recorded above.

## Native wrapped ISO dates

Explicitly select `PdfNativeLayoutOptions.CellTextJoin.WRAPPED_ISO_DATE` through
`withCellTextJoin`. An entire valid ASCII ISO date split after hyphens across two
or three aligned upright native runs is joined without inserted spaces. Defaults,
invalid/ambiguous dates, ordinary text, native heuristic tables and OCR are unchanged.
Original cell text limits apply before joining. Changed provider-owned tables carry
`pdf_table_cell_text_policy=wrapped_iso_date_v1` and a whole-table join count; fragments
omit the count and retain it in original-element provenance.

The fixed2025 publisher table improves116/136 to131/136 exact logical span/text
anchors, preserving nine headers and16x9 geometry;20 other fixed selected captures
remain unchanged. This is development evidence, not held-out accuracy or a header
segmentation fix. Source/spans and known misses remain in the reports.

Upgrade: `PdfNativeLayoutOptions` gains its fourth record component, `cellTextJoin`.
The old three-argument constructor and accessors remain with SPACE_SEPARATED behavior.
Record patterns, reflection, serialization and equality/hash/string shape consumers
need review; a previously compiled constructor consumer runs on both Java21/25.
This change is included in the cumulative beta.6 candidate described above.

### Source-declared word wraps

The new `SOURCE_SOFT_HYPHENS_AND_WRAPPED_ISO_DATE` cell-text policy uses explicit source
soft-hyphen hints in supported tagged cells. It preserves ordinary hard hyphens and competing
alternatives, exact glyph ownership, geometry and original cell character limits. Use it with
the source-tagged factories; provider-only cells retain the wrapped ISO-date policy.
Existing factories and joining modes preserve their behavior. Source-tag quality still varies.

On two fixed PLOS tables, exact logical span/text matches improve135/136 to136/136 and
13/15 to15/15. All21 other selected regions remain unchanged on Java21/25; these are
development measurements rather than representative accuracy. Full994-test builds pass.

### Explicit OCR binarization

`TesseractOcr.create(options, TesseractThresholding)` and `createWithWords` overloads expose
fixed Tesseract5 Otsu, adaptive Otsu and Sauvola policies. Existing factories keep engine
defaults; the options record and constructors are unchanged. This is opt-in configuration,
not automatic image enhancement or guaranteed recognition improvement. Borrowed raster
geometry, shared admission, deadlines, cleanup and output limits remain in force.

A uniform24-case scan/model/threshold evaluation matches across Java21/25. Sauvola
reduces1835 Fraktur character edits51 to44, but worsens both degraded sources; defaults
remain unchanged. Full996-test builds pass. See the retained complete threshold evidence.

### Explicit OCR raster resolution

The line and word factories also accept `(options, thresholding, sourceDpi)`. This forwards
known raster resolution as engine metadata without resampling or changing coordinates.
Use the actual render/scan resolution,70 through2400DPI, and separate providers when it varies.
Existing overloads preserve engine defaults. This supports reproducible scan configuration;
it does not establish improved recognition on historical or degraded scans.

A separate24-case replay at source-declared300/600DPI preserves exact rendered pixels and
matches across Java21/25. It improves some adaptive results while worsening others; all
outcomes and unchanged reference denominators are retained. Both full builds pass1001 tests.
See [source-resolution evidence](../../benchmarks/review/pdf-scan-source-resolution/README.md).

### Password-protected PDFs

Built-in PDF partitioners and font inspectors accept `.withPasswords(PdfPasswordProvider)`.
Configuration copies the existing strategy and requests one fresh credential only when needed.
Native/tagged/provider tables, OCR/orientation/cell providers, actual PDFBox permissions and
resource limits remain active. Returned credential arrays transfer ownership and are cleared
after opening attempts; PDFBox still requires temporary String copies. Existing factories and
discovery keep their previous no-credential behavior. No password cracking or credential cache
is added. See [PDF configuration](../pdf-support.md#password-protected-documents).
