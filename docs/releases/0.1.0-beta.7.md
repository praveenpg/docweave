# DocWeave 0.1.0-beta.7 — proposed release notes

## Release status

State: **draft, unpublished**. This is a cumulative summary of the current Unreleased
changes since beta.6, not a prepared Maven Central candidate. The repository version
remains `0.1.0-SNAPSHOT`. No version bump, signing, tag, GitHub release or upload is
performed by preparing these notes. Pin the final source revision and refresh the
verification evidence when an actual candidate is prepared. Publication remains deferred.

## Changes

- **Simpler PDF configuration:** interface-based `PdfPartitioner.builder()` and explicit
  `PdfStrategy.FAST`, `AUTO`, `HI_RES`, `OCR_ONLY` presets alongside existing factories.
  Engines, languages and models remain caller-provided. AUTO can use configured OCR on
  textless pages; OCR_ONLY recognizes every page; HI_RES requires configured word OCR
  and layout. No implicit model downloads, language guessing or error fallback.
- **Native reading and captions:** optional column compound-wrap grouping, including a
  mode retaining arbitrary-angle labels; preserve physical source hyphens and omit only
  supported generated separators. Optional numbered image-adjacent/edge-aligned caption
  classification retains original strings and bounds. Default line/type behavior stays.
- **Source paragraphs:** page-local fragments and explicit document-level assembly,
  source-line-wrap joining and nearby inline-script handling. These remain caller-selected
  and source-bound; no global semantic order or cross-page dehyphenation guarantee.
- **Tables:** explicit native financial/aligned and shaded-row policies, compact numeric
  padding/inline-script options, source-supported shaded-header fixes and tagged-table
  logical envelopes/attribute classes/caption references. Explicit cell policies can retain
  line breaks or interpret source wraps, ISO dates and nearby script runs. Unsupported or
  ambiguous topology retains its documented fallback rather than invented structure.
- **Multi-page table context:** optional provider-declared single, repeated-prefix and
  merged-layout header continuation. Provider header roles reach shared table chunking;
  source-only counts/wrap evidence remain in original provenance rather than being copied
  as whole-table claims onto fragments.
- **Images:** normalized mask dimensions obey pixel limits before decoding; solid stencil
  PNGs preserve invocation paint and transparency. Ordered source-image corners now retain
  rotation/mirror/shear independently of enclosing bounds, and `PdfCoordinateConverter`
  converts both geometry maps. Source placement remains distinct from page compositing.
- **Repeated margins:** equivalent numeric zero rotations and Unicode whitespace now
  match consistently in the explicit header/footer classifier. Preserve source text,
  geometry, body-duplicate vetoes and configured first-page handling.
- **Rendering evidence:** native rule/shading checks exclude zero-opacity strokes and
  supported empty/disjoint inherited or rectangular path clips. Optional native text
  filtering handles rendering mode, source alpha and empty inherited clips. These are
  conservative source checks, not a complete rendered-visibility engine.
- **Optional OCR/layout:** managed YOLOX detection through `OnnxTableLayout.createWithYoloX`,
  explicit Tesseract SINGLE_COLUMN segmentation and LOCAL_WHITEPOINT page preprocessing.
  Preserve existing bounded sessions/deadlines and defaults. Whitepoint helps one measured
  low-contrast source and regresses others; it is not automatic or a general recommendation.
- **Allocation:** compatible read-only binary context views avoid extra full-array copies
  in PDF loading/fingerprints. Original-element provenance JSON streams into compression
  under its existing UTF-8 budget. Whole inputs/output graphs still materialize; these
  changes do not establish a total heap or execution-time limit.

### Minimal native configuration

```java
import dev.docweave.partition.PdfOptions;
import dev.docweave.partition.PdfPartitioner;

var options = PdfOptions.defaults()
        .withTextLayout(PdfOptions.TextLayout.ORIENTED_COLUMN_PARAGRAPHS_COMPOUND_WRAPS)
        .withFigureCaptions(PdfOptions.FigureCaptions.IMAGE_EDGE_ALIGNED_NUMBERED_TITLES);
var partitioner = PdfPartitioner.create(options);
```

Install this partitioner through the existing `PartitionerRegistry`/`DocWeave` facade.
These enum values belong to the development candidate, not published beta.6.
The PDF guide includes explicit optional OCR/provider setup; supplying the native
configuration alone does not start an OCR engine or load a layout model.

### Image geometry

Native image metadata adds `pdf_image_coordinates` with four source-unit-square
corners in00,10,11,01 order and the displayed page frame. The existing element
`coordinates` remains its enclosing rectangle. `PdfCoordinateConverter.create()`
converts both maps to physical points/millimeters or virtual page pixels without
reordering corners, changing the PNG or mutating the original element. See the
[complete corner contract](../pdf-support.md#ordered-source-image-placement-corners-unreleased).

## Upgrade and compatibility

- Maven group remains `io.docweave`; selective modules and Java packages `dev.docweave`
  remain. Align module versions when the candidate is actually released. Java21 without
  preview remains the baseline; virtual-thread document concurrency remains available.
- Existing factories and compatibility constructors remain. New enum constants require
  updating exhaustive switches. `PdfTaggedParagraphOptions` has added record components;
  review record patterns, reflection, serialization and equality/string-shape assumptions
  even when an older constructor still compiles. See the detailed changelog per component.
- Image metadata is additive; consumers comparing exact complete metadata must account
  for the new field. Existing text, IDs, enclosing image bounds and payloads are retained.
  Strict coordinate conversion also validates the additional map when present.
- Provenance retains the same decoded JSON contract; raw compressed byte sequences may
  differ after streaming. Avoid comparing compressed bytes as semantic identity.
- Optional Tesseract/ONNX artifacts remain explicit. Caller-supplied binaries/weights,
  language data, resource ownership and configured limits remain required.

## Known limitations and remaining work

PDF table/layout/OCR/image support is not general Unstructured parity or full rendered
fidelity. Financial multi-page statements still lose/merge rows or separate title/header
content. Historical/degraded OCR improvements are source-dependent. Native extraction can
retain source hard hyphens, NBSP and hidden/clipped text outside explicitly supported
filters; source XML text need not equal physical PDF text. Broad semantic order, calibrated
confidence, diverse independent acceptance, page compositing and vector figure interpretation
remain open. PDFBox/codecs can allocate or delay cancellation before callbacks.

The eLife example has known sidebar/body interleaving. See the
[PDF progress and remaining gates](../pdf-progress.md) for retained evidence and other
limitations. Cross-format contextual enrichment is described below; broader retrieval
quality and further DOCX enhancements remain open.

Native graphics also isolate unfinished caller paths across normal, nested and
transparency-group forms, preserving ruled tables and deferred clips without
resetting shared budgets. Owned render-equivalent controls and existing original
scientific/business regression records pass; this is not full compositing support.

Native paragraph grouping preserves existing list boundaries when marker separators
are Unicode whitespace, including NBSP and narrow NBSP. Original characters and
geometry remain unchanged; no new marker syntax or list hierarchy is inferred.

## Optional contextual chunk enrichment

The snapshot adds `ContextualChunker` and `ChunkContextProvider` interface services
with immutable request/context/result/options value types. Generate document-aware
context after existing chunk splitting using an explicitly supplied local or hosted
provider. Original text, IDs, metadata and provenance remain unchanged; generated
context and `embeddingText()` are separate. All inputs are preflighted, concurrency
uses a bounded Java21 virtual-thread window, and whole-call deadlines/cancellation
remain explicit. Failure policy either fails the invocation or retains an original-only
result. No model client/dependency, automatic request, retry or provider discovery
is added. See [usage and limitations](../contextual-chunking.md).

JVM controls cover eight actual formats/both chunk strategies, managed provider behavior,
HTTP protocol failures and retrieval replay. The separate two-JAR built-snapshot consumer
passes. A runnable Ollama example plus explicit embedding capture retains source/model
identities and all failed/missing queries. One authored three-chunk/five-query live check
improved top1 hits from3/5 to5/5; larger independent retrieval quality remains unmeasured.
No general gain or parity claim is made. Original chunking goldens remain unchanged.

The Ollama example also accepts frozen source chunks, preserving reference IDs without
repartitioning. An owned PDF/DOCX/HTML check freezes12questions before generation and
retains all9chunks: top1hits10/12 versus11/12 with context; one revenue miss remains.
These small integration checks do not close independent real-world retrieval acceptance.

Native images also retain `pdf_image_graphics_state`: invocation alpha, resolved blend
mode, graphics-state soft-mask presence and alpha-source flag. PNG samples, source
occurrence accounting and placement geometry remain unchanged. Current-stream state
is separate from enclosing group composition and final page visibility. Four new JVM
controls cover source paint/restoration, ordinary/transparency forms, masks and JSON/
coordinate preservation; see [the source-state contract](../pdf-support.md#source-image-graphics-state-unreleased).

Native table evidence excludes drawing commands from invisible Type3 glyph programs
while retaining visible glyph paint, ordinary page rules, source-image accounting and
shared operator limits. An owned render-equivalent counterexample previously produced
a false Table; it now retains ordinary text. Five new JVM controls cover stroked, filled
and combined paint, image inventory, state restoration, cancellation and budget exhaustion.
See [source visibility behavior](../pdf-support.md#invisible-type3-glyphs-and-native-table-evidence-unreleased).

Type3 glyph traversal also has an explicit limit of 64 active character programs.
Deeper or cyclic programs fail with `INPUT_TOO_LARGE`. A serialized self-referencing
font previously exhausted the graphics visitor stack; the public API now returns the
typed error. Finite 64/65-level and post-failure controls pass. This is a source-program
limit, not a total stack or heap guarantee for PDFBox or codecs.

Native form traversal now reports `INPUT_TOO_LARGE` beyond 50 nested form invocations,
including cycles, instead of returning success with silently truncated content. Images
inside the 50th form remain eligible. Ordinary forms and transparency groups are covered
by owned fixtures and a six-JAR packaged public API check. See the
[form-depth evidence](../../benchmarks/review/pdf-form-depth/README.md).

Type3 glyph drawing paths are isolated from unfinished caller paths. Glyph strokes
retain their own paint while the caller's path survives completion or traversal failure.
See the [Type3 path regression](../../benchmarks/review/pdf-type3-path/README.md).

Native rule traversal now honors single affine-transformed rectangle-operator clips,
removing wholly disjoint border evidence that could previously create a false table.
Partial clipping and final image compositing remain outside this bounded correction.
See the [clip regression](../../benchmarks/review/pdf-skewed-rectangle-clips/README.md).

Native rule clipping also accepts bounded finite four-corner line-built paths, fixing
false tables from skewed clips expressed without a rectangle operator. Both winding
rules, visible restoration and rotated crop/UserUnit controls are covered. The unsuccessful
financial row-gap experiment remains unpromoted with all original reference rows retained.

Explicit partially ruled table extraction now separates adjacent header text across
supported source column boundaries. The retained statistics original improves from
339/350 to 350/350 saved CSV positions; body cells and table bounds remain unchanged.
Other 17 retained case/profile outputs are equal. This does not close the broader
business-table quality gate. See the [header evidence](../../benchmarks/review/pdf-partial-header-boundaries/README.md).

Native rule traversal now honors compound clips made from two rectangle operators,
including their source winding rule. This removes false tables from fully hidden grids;
visible/nonzero-winding and form-restoration controls remain. Larger compound paths,
clip-hole visibility and final image compositing remain outside this subset.
