# DocWeave 0.1.0-beta.12

## Release status

State: **proposed; not yet published**. Full-library scope: the parent and all deployable library modules use
`0.1.0-beta.12`. Integration and validation harnesses are not published. The Studio SDK is a separate project and
is not part of this release. Jenkins will create the immutable annotated `v0.1.0-beta.12` tag and GitHub prerelease
at the verified public source revision before any Maven Central upload.

The previous Maven Central release is **0.1.0-beta.10**. **0.1.0-beta.11 was an internal-only build that was never
published to Maven Central; `0.1.0-beta.11` does not exist on Central.** These notes therefore cover every change
since beta.10.

An internal-only build of 0.1.0-beta.12 was produced earlier from the same source for the maintainers' own use. The
Central release is a separate build of that source. DocWeave builds are not byte-for-byte reproducible, so its
artifacts are expected to differ in bytes from the internal build; only the Central artifacts are the public
0.1.0-beta.12.

## Changes

See the [changelog](../../CHANGELOG.md#010-beta12) for the complete entries.

### Breaking: contextual chunk enrichment removed

`ContextualChunker`, `ChunkContextProvider`, `ContextualChunk` and `ContextualChunkOptions`, and their
implementation, are removed from `io.docweave:docweave-chunking` and the `io.docweave:docweave` convenience
artifact. Code that uses them no longer compiles. The API was beta; it was removed directly, without a published
deprecation release. Contextual enrichment is DocWeave Studio functionality. To keep the pattern, copy it from the
0.1.0-beta.10 sources (Apache-2.0), the last published version that contains it, or stay on 0.1.0-beta.10 until you
migrate. See [contextual chunk enrichment](../contextual-chunking.md) and the
[decision record](../decisions/0001-contextual-enrichment-boundary.md). Ordinary chunking is unaffected.

### PDF: optional per-page operator ceiling

`PdfOptions.UNLIMITED_OPERATORS` (`0`) as `maxOperatorsPerPage` disables the per-page content-operator ceiling;
`PdfOptions.withMaxOperatorsPerPage(int)` and `operatorsLimited()` are new. Without the ceiling, the page, glyph and
image budgets and the form-depth limit still apply, but processing time is bounded only by the caller's deadline or
cancellation, so use it with one, or with trusted input. Negative values are rejected. The default ceiling in
`PdfOptions.defaults()` is unchanged (100,000), and positive ceilings are enforced as before. The `INPUT_TOO_LARGE`
message now states the effective limit. This is opt-in.

### PDF: new memory bounds and cancellation checks

Memory that grows with a page's content is now bounded independently of the operator ceiling, and cancellation is
checked more often:

- A content stream with more than **4,096 nested graphics states** (`q` without `Q`) fails with `INPUT_TOO_LARGE`.
  This applies **at default settings** and at any operator ceiling, in every pass, including rendering for OCR,
  table-layout assistance and page crops. A PDF that beta.10 processed can now fail for this reason.
- A page with more than 100,000 image occurrences fails with `INPUT_TOO_LARGE`.
- A page retains at most 500,000 line segments for rule-based table detection. Past that it is read without rule or
  shaded-row tables, image clip bounds on it may be incomplete, and a `PDF_EXTRACTION_LIMITATION` warning names the
  page. Under the default ceiling a page cannot reach this bound, but a caller with an explicit ceiling above about
  125,000 operators can now get the warning on a page that previously kept all of its geometry.
- Tagged extraction stops claiming a page's tags past 100,000 distinct marked-content identifiers; the page is then
  read as untagged.
- Thread interruption is checked on every operator of the text pass, font inspection and page rendering, including
  inside form XObjects, where PDFBox would otherwise log and skip an interrupted form.

### Partition progress (#33)

`DocWeave.partition(source, options, listener)` reports optional, content-free `PartitionProgress` snapshots
(PREPARING, EXTRACTING, ASSEMBLING, DONE). PDF reports completed/total `pages` for native, `OCR_ONLY` and `HI_RES`
routing; other formats report indeterminate phases. Calls without a listener are unchanged. See
[partition progress](../partition-progress.md).

### Chunk overlap metadata

A chunk that begins with text repeated from the preceding chunk carries the integer metadata field
`overlap_prefix_characters` (`Chunker.OVERLAP_PREFIX_CHARACTERS`) when the repeated text exactly ends the preceding
emitted chunk. This is a DocWeave extension absent from upstream output; chunks without established overlap omit it.

```xml
<dependency>
    <groupId>io.docweave</groupId>
    <artifactId>docweave-pdf</artifactId>
    <version>0.1.0-beta.12</version>
</dependency>
```

## Upgrade and compatibility

- Java 21 minimum, without preview features; library bytecode remains Java 21. The S3Mock test helper uses Java 25.
- All DocWeave module versions must align. The parent remains `io.docweave:docweave-parent`, and the all-formats
  artifact remains `io.docweave:docweave`. Optional remote S3, OCR and layout integrations remain opt-in.
- No third-party dependency versions change since beta.10.
- **Source-breaking:** code using the removed contextual enrichment types must migrate before upgrading (see above).
- **Behavior:** the PDF bounds above can turn previously accepted inputs into `INPUT_TOO_LARGE` failures, most
  notably the 4,096 graphics-state nesting bound at default settings. Callers relying on unlimited geometry with a
  high explicit operator ceiling can see the new line-segment warning.
- **Additive:** `PartitionContext.progress()` and the listener `DocWeave.partition` overload are default methods, so
  existing custom contexts and facades compile unchanged. A `PartitionContext` decorator should forward
  `progress()`. Chunk output can gain the `overlap_prefix_characters` metadata field.
- Moving from beta.10 requires no data migration. Earlier-release migrations described in the beta.9 notes still
  apply when skipping releases. There is no beta.11 on Central to upgrade through.
- Published beta.10 coordinates and bytes are not replaced. This release does not upgrade or deploy Studio.

## Verification

Publication remains conditional on the existing Jenkins gates: full Java 21 reactor verification, strict Javadoc,
required S3Mock qualification, archive/license/bytecode checks, standalone adapter consumers against the exact
captured artifacts, signing, durable candidate storage, and Maven Central validation and publication.
Final build identifiers, test counts, publication identity and public-checksum verification will be recorded only
after those steps complete. Beta.10's verification and any internal-build results are not a claim that the beta.12
Central candidate already passed.

## Known limitations

The [beta.9 limitations](0.1.0-beta.9.md#known-limitations), retained by beta.10, still apply: compatible-service S3
qualification is not real AWS S3 qualification; HTTP/Azure/GCS remote resolvers are not included; optional
OCR/layout engines and models require explicit configuration; PDF/OCR quality retains its documented boundaries;
Native Image is not qualified. In addition:

- With `UNLIMITED_OPERATORS`, processing time is bounded only by the caller's deadline or cancellation.
- Batch services (`DocumentBatch`, `BatchProcessor`) do not yet accept a per-document progress listener, and only PDF
  reports progress units.
