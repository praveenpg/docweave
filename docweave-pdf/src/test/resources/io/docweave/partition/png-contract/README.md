# PNG raster contract fixtures

Both owned fixtures are 8×8 RGB images with all 64 pixels opaque red (`ARGB=ffff0000`). They were generated by the standard JDK ImageIO PNG writer; no third-party document or model is involved.

- `red-frozen.png`: SHA-256 `fc413db821e509581923499bea1ad6eaf402a408990859ea51c25765a6736b27`, matching the unchanged historical image-contract and rendered-crop packets. Reproduced on the local Amazon Java 21.0.8 runtime.
- `red-alternate-deflate.png`: SHA-256 `c8f558de7f23d872b4d1253bca6c24a14aca3fa4507e614e80467f025eb60599`, reproduced on the Jenkins Temurin Java 21.0.13 runtime.

Each PNG is 75 bytes. IHDR and IEND match; the 18-byte IDAT payloads differ but inflate to identical 200-byte scanline data. The historical checksum remains asserted against the frozen fixture. Newly encoded extraction payloads must match its dimensions and **every** decoded ARGB pixel, not an environment-specific compressed representation. Tests also refuse a changed color, changed alpha and changed width. Existing before/after extraction equality and all transparency/clipping assertions remain intact.

This corrects test portability only. Production PNG encoding, extraction behavior and historical evidence are unchanged. It does not establish why the two runtime distributions produce different DEFLATE bytes, nor require byte-identical PNG output across JDK distributions.
